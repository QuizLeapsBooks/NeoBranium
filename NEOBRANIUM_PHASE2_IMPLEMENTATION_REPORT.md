# NeoBranium Phase 2 Implementation Report

1. **Files created or modified:** Added `services/aiUsageTracker.js`, `services/aiUsageTracker.test.js`, and this report; updated `server.js`, `routes/paperRoutes.js`, `NeoBoard/handwriting-recognition.js`, `NeoBoard/handwriting-recognition.test.js`, `NeoBot/backend/routes/session.js`, and `NeoBot/backend/routes/proxy.js`.
2. **Features instrumented:** Chatbot (including paper-generation task), NeoLens solve/quiz/practice, AI Board stream/analyze/rephrase, NeoBoard handwriting/selection, paper generation/model answers/evaluation, ElevenLabs TTS, Gemini Live token provisioning, and authenticated Live proxy sessions.
3. **Providers and metrics supported:** Gemini and Groq input/output/explicit total token normalization; nullable unknown usage and explicit estimate source; provider attempts and fallback outcomes; image count/bytes/dimensions where validated; TTS input characters and response bytes when exposed; Live session duration and bidirectional WebSocket frame bytes. Operational modality metrics are not represented as provider-billed units.
4. **Tests executed and results:** Tracker/handwriting tests passed (18/18); NeoBook service tests passed (9/9); syntax checks and `git diff --check` passed. `paper-generator.test.js` had one unrelated syllabus-guidance assertion failure (expected “competency-focused” wording in an unchanged syllabus helper).
5. **Features not yet instrumented:** NeoBook remains on its native accounting and is intentionally not emitted to the central event contract. Direct-to-Gemini Live session duration and audio-specific/billable metrics are unavailable to the backend; generic AI conversation-history routes do not invoke models.
6. **Known limitations:** Events are emitted asynchronously to in-process subscribers only; there is no durable storage in this phase and events are lost on restart. Provider usage is unavailable when response metadata is absent; streaming Groq usage is not requested. Some route validation failures produce no provider attempt. Existing quota-before-validation behavior is unchanged.
7. **NeoBook accounting:** No NeoBook accounting or reservation code was changed, and no duplicate NeoBook usage events were added. Existing daily usage remains feature-unclassified; future attribution requires a safe change to the native ledger/artifact writes.
8. **Deployment:** No deployment occurred. No Firebase usage collection, rules, indexes, or database records were changed.
