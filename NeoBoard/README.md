# NeoBranium Blackboard foundation

The independent normal blackboard is served at **`/NeoBoard/board.html`**. The existing `/ai-board/ai-board.html` implementation remains separate and unchanged. The board has no runtime service dependencies; state is saved to browser local storage and can be exported as PNG or versioned JSON.

## Modules and extension points

- `board-app.js` composes the interface, tools, autosave and browser input. It emits document, object, selection and history events through `BoardEventBus`.
- `board-engine.js` owns the high-DPI canvas, viewport transform, render loop and object hit testing. Input coordinates convert to board-space through `toBoard`; zoom/pan do not modify document data. Extensions can call `registerObjectRenderer(type, renderer)` to draw their serializable object type; unknown registered object types round-trip safely and are skipped by the default renderer.
- `board-core.js` contains `StrokeManager`, `ObjectManager`, `SelectionEngine`, structured text and shape data, `HistoryManager`, `BoardPersistence`, validation/migration gate, `BoardContextProvider`, `BoardActionRegistry`, `ExtensionRegistry`, and `BoardEventBus`.
- `BoardContextProvider.snapshot()` returns a safe structured snapshot with stable IDs and selected objects. Each stroke includes its calculated spatial `bounds`. `region({x,y,width,height})` returns intersecting strokes and objects.
- `Select` (V) and `AI Select` (A) select clicked items or a marquee region, render a screen-space-stable group boundary and handles, and support group move, deselect and delete. Shift adds to an existing selection. Rectangles and ellipses resize from handles; text and handwritten strokes remain at their original dimensions when group resizing, and other shapes only move with the group. Selection geometry is rendered as an overlay and is not included in board data or PNG export. Pointer Events cover mouse, pen and touch.
- Each selection snapshot contains `documentId`, `objectIds`, `strokeIds`, `itemIds`, combined `bounds`, and cloned `objects` / `strokes`; stroke entries have `type: 'stroke'` and calculated `bounds`, while typed text retains its editable `text` and dimensions. `learning-recognition.js` applies local extensible rules to typed text. The Learning Tools **Analyze selection** action rasterizes only selected original strokes and supported objects into a padded, high-resolution PNG; it never screenshots the UI. Selected IDs, bounds and object types accompany the crop. The panel displays the validated recognition, allows correction, and renders only available contextual handlers. `window.NeoBraniumBlackboard.getSelection()` and `.getSelectedContent()` return this safe context; `.subscribeSelection(handler)` subscribes to `selection:changed` and returns an unsubscribe function; `.deselect()` clears it.
- `BoardActionRegistry.register({id,label,objectTypes,subject?,metadata?,availability?,handler})` registers contextual operations. `list({objectTypes,subject,metadata})` returns safe descriptors; `execute(id,context)` invokes the registered handler. The Learning Tools panel displays recognition, a manual subject override, correction field, graph semantics selector, supported actions, and a custom question field. Implemented math actions solve supported linear/quadratic equations, find roots, explain standard form, factor supported monic integer quadratics, and graph degree-2 polynomials deterministically. Graphs render in a result panel and can be inserted as structured, movable, resizable board objects that persist in JSON/local storage and export to PNG. Function mode requires a zero right-hand side; equation mode graphs left minus right against zero. Text copy/edit, a small offline definition set, and example sentences are also implemented. Unsupported subject actions are omitted. `window.NeoBraniumBlackboard.registerAction(action)` lets an extension add a real handler; `registerRecognitionRule(rule)` adds local rules. Both return unregister functions.
- `ExtensionRegistry.register({id,name,version,initialize})` gives independent modules the composed events, context, action registry and registry. It rejects duplicate IDs and returns an unregister function.
- Future subject suggestions can use `getSelection()` / `selection:changed`; handwriting recognition uses the secure backend endpoint below. Model suggested action IDs are allowlisted, intersected with available local handlers and cannot replace preset results. A future provider adapter can implement `request({operation,context,options}) => Promise<structured result>` as described by `providerAdapterContract`. No image search is included. Action results render independently in the sidebar and may offer insertion of supported text results into the board.

## Handwriting recognition

The Learning Tools panel sends selected text and/or a crop to `POST /api/blackboard/analyze-selection` on explicit request. `POST /api/blackboard/recognize-handwriting` remains available for image-only recognition. Both routes use Firebase `requireAuth`, the Firestore UID quota (`QUOTA_HANDWRITING_DAILY`, default 20/day), a 20 requests / 15 minutes per UID limiter, and a one in-flight request per UID guard. PNG crops are limited to 7 MB encoded, 4096×4096 pixels and 12 MP. Provider keys are read only by the backend. Gemini tries `gemini-3.8-flash` and `gemini-3.6-flash`; after transient provider quota, availability, or timeout errors, the service falls back to Groq using `GROQ_API_KEY`. Text uses `GROQ_MODEL`; handwriting/images use `GROQ_VISION_MODEL` (default `qwen/qwen3.8-27b`). Both provider paths return data through the same structured result validator and action allowlist. Graph points are generated locally. The backend does not persist or log images. The response includes ambiguity and confirmation fields; uncertain readings require student confirmation before contextual actions appear. Mathematical graph rendering and solving use deterministic local code. A custom question uses the same authenticated, validated selection endpoint and is treated as student content. Missing both provider configurations returns `AI_NOT_CONFIGURED` and the board remains usable.

Gemini model defaults are separated by workload: routine text and paper generation use `gemini-3.5-flash-lite`; image understanding and answer-sheet evaluation use `gemini-3.8-flash`; handwriting uses `gemini-3.8-flash`; Live uses `gemini-3.8-live`. Optional server-only overrides are `GEMINI_ROUTINE_MODEL`, `GEMINI_VISION_MODEL`, `GEMINI_HANDWRITING_MODEL`, `GEMINI_PAPER_MODEL`, and `GEMINI_LIVE_MODEL`. Overrides are accepted only when they match the appropriate model family in the supported model registry. Legacy `GEMINI_MODEL` remains a fallback only when it is a supported model for that workload. Gemini TTS and image-generation models are not wired into these routes: the current voice service uses its existing TTS provider, and board graphs are deterministic SVGs.

Focused checks: `node --test NeoBoard/learning-recognition.test.js NeoBoard/handwriting-recognition.test.js`. These use mocked Gemini responses; live recognition requires a valid server-side key and an available Firebase-authenticated session.
- Future floating result panels follow `floatingPanelContract` in `board-core.js`: descriptor fields are `id`, `title`, DOM `content`, board-space `position` and `size`; host events are `panel:closed`, `panel:moved`, and `panel:resized`. User text should be inserted as text nodes, never interpreted as HTML.

Documents carry `schemaVersion`, board ID, timestamps, display settings, stroke point arrays, stable object IDs, geometry, z-order by array order, and extensible metadata. `validateDocument` rejects malformed content and unsupported future versions. `migrateDocument` is the explicit migration gate: add sequential schema transformations there before raising `SCHEMA_VERSION`; unsupported versions fail visibly instead of being silently rewritten. Current built-in object types are text, line, arrow, rectangle and ellipse. Other valid type identifiers and their payload/relationships round-trip, and extensions can register their renderer before restoring those objects.

## Current controls

Pen P, eraser E, select V, AI Select A, text T; hold Space or choose Pan to move the viewport; Ctrl/Cmd+Z and Ctrl/Cmd+Y undo/redo; Delete removes selected objects. Text editing is via double-click or toolbar insertion. AI Select uses the group handles to resize structured objects and handwritten strokes together. Clear asks for confirmation. Saved boards are device-local and selectable through **Saved boards**; JSON import validates the document before replacing the active board.

Run focused foundation checks with `node --test NeoBoard/board-core.test.js`. This is a frontend-only module; the Express static allowlist includes `/neoboard/`, while Firebase Hosting already publishes project files from the repository root.
