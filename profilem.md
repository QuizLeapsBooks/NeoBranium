# Identified Code Problems

After analyzing the codebase and recent server logs, here are the identified issues:

### 1. Prompt Conflict (Critical)
The backend `server.js` and the frontend `js-generate.js` are sending conflicting instructions to the AI. 
- **Server**: Injects "You are a programming expert. Provide code examples with explanations." into the system prompt.
- **Frontend**: Explicitly tells the AI "You are a professional Indian exam paper setter AI." 
This confuses the AI, leading to suboptimal or inconsistent results (e.g., trying to explain code when generating a math paper).

### 2. False Positive Category Detection
The `detectQueryType` function in `server.js` uses the keyword `class` to categorize a request as `code`. 
```javascript
code: /...|class|.../i
```
Since the Paper Generator always includes a field like `- Class: 8`, every single paper generation request is incorrectly flagged as a "programming" request.

### 3. Hardcoded Interaction Rules
The server appends fixed instructions to every user message:
```javascript
"Respond in a helpful, educational manner. Use markdown for formatting.\nIf explaining code, always provide examples.\nBe encouraging and patient with learners."
```
This is fine for a general chat bot but interferes with specialized tools like the **Paper Generator**, which requires a very specific, professional response format.

### 4. Client-Side Only Limits (Security)
The `chatCount` and `paperCount` limits depend entirely on `localStorage`. A moderately savvy user can bypass these limits by:
- Clearing browser storage.
- Using an Incognito/Private window.
- Manually editing values via the browser console.
For a production system, these should ideally be checked against a session or database on the backend.

### 5. Redundant Prompting
The `aiPrompt` generated by the frontend is extremely long. When wrapped with the server's own system prompt and hardcoded instructions, it risks hitting token limits or diluting the AI's "attention" on the actual generation task.

### 6. Mixed-Use API Endpoint
The `/api/chat` endpoint is being treated as a "one size fits all" gateway. It should ideally differentiate between a free-form chat and a structured task like paper generation.
